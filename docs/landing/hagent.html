Install Hagent on your device

Download the ZIP, extract it, and follow the steps for your operating system. Python 3.11 or newer is recommended.

Windows

Primary tested platform. Open PowerShell inside the extracted hagent folder.

  1. Install Python 3.11+ and Git.
  2. Download and extract Hagent.
  3. Run the commands below.
  4. Open http://127.0.0.1:8000.
py -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip install -e .
.venv\Scripts\hagent.exe serve

macOS or Linux

Open Terminal inside the extracted hagent folder.

  1. Install Python 3.11+ and Git.
  2. Download and extract Hagent.
  3. Run the commands below.
  4. Open http://127.0.0.1:8000.
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -e .
hagent serve
Before enabling terminal access: agents run with the permissions of the operating-system account that starts Hagent. Use a dedicated account, container, VM, or isolated worker device for autonomous work. Keep the default loopback address unless you configure Hagent accounts and protected HTTPS or Tailscale access.

What's new in 0.2.3

Released October 22, 2026. Connect your accounts and tools directly, and keep agent workflows moving.

Gmail and Google Drive

Sign in with Google to search and read email, find files, and read Google Docs. Access is read-only and you choose which agents can use each account. The installation owner configures Google sign-in once.

One Connections page

Manage Google accounts, direct JSON APIs, and MCP servers together. Test connections and assign agent access from the same page.

Simpler API setup

Enter a name, endpoint URL, and API key for a direct read-only API. Custom authentication stays under Advanced. MCP supports installed local commands and remote HTTP or SSE servers.

Smoother Google sign-in

The return from Google keeps your Hagent session. Connected accounts show their status instead of repeating the sign-in prompt. Credentials are encrypted locally, with refresh tokens and single-use OAuth state.

Cleaner boards and schedules

Internal maintenance projects stay off the main board by default. Unfiltered autopilots target active work rather than repeatedly running review or completed tasks.

More reliable workflows

Reassignment queues the new agent, recent issue discussion follows the work, and parent verification waits for unfinished children. Failed worktree setup is recorded instead of leaving a run stuck.

How good is Hagent today?

An honest release assessment for version 0.2.3—not a synthetic performance benchmark.

Provider flexibility

8.5/10

Broad cloud, local-model, and CLI adapter support with per-agent primary and backup runtimes.

Workflow depth

8/10

Projects, issue boards, squads, skills, approvals, schedules, delegation, verification, and run history already work together.

Local control

8.5/10

Your database and orchestration layer stay on your machine; provider calls depend on the runtime you choose.

Beginner setup

6.5/10

Clear for technical users, but it is still a source install rather than a one-click signed desktop installer.

Production maturity

5.5/10

Promising and test-backed, but still an early release without packaged containers, automatic upgrades, or enterprise support.

Overall for technical early adopters

7.5/10

A serious, unusually capable local orchestration foundation—best for builders willing to configure and supervise it.

Best fit now: developers, AI power users, researchers, and trusted small teams. If you need a polished one-click consumer app or unattended enterprise production platform, wait for a later release.
